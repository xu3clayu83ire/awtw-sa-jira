# 需求文件 — 網頁 UI 改用文件站樣式呈現

> 本文件模擬需求提出單位的視角撰寫，描述「要什麼」，不描述「怎麼做」。

## 需求背景與痛點

現有網頁（功能選單、文件檢視器、進度儀表板全部擠在同一頁）排版陽春，看不出結構，也沒有專屬網址可以直接連到特定功能或特定頁面，使用體驗差。團隊已經在別的專案（`awtw-short-url-service`）用文件站樣式呈現規格文件，體驗很好，希望比照辦理。

## 期望達成的目標

有一個排版整齊、有清楚導覽結構的網站，可以瀏覽每個功能的規格文件（需求文件、系統設計文件、開發任務清單），也能看到該功能對應的 Jira 進度，視覺風格統一、不用自己刻版面。

## 功能期望（業務角度）

1. 左側有導覽選單，依功能分類，能看到工作區裡所有已產出規格的功能清單。
2. 每個功能底下能個別瀏覽需求文件、系統設計文件、開發任務清單，排版清楚、有目錄。
3. 有搜尋功能，可以直接找到想看的文件內容。
4. 每個功能有一個獨立的「進度儀表板」頁面，顯示這個功能對應的 Jira 票即時進度：總票數、依狀態分類的數量、每張票的角色與執行方式（AI 或人工）。
5. 網站要支援淺色與深色兩種顯示模式。
6. 進度儀表板的資料要能自動更新，不用手動重新整理頁面。

## 優先順序

| 優先度 | 項目 |
|---|---|
| Must | 文件瀏覽（左側選單、目錄、搜尋） |
| Must | 進度儀表板（依功能顯示 Jira 票進度） |
| Must | 淺色／深色模式 |
| Should | 進度儀表板自動更新 |

## 範圍邊界（不做的事）

- 不做文件的線上編輯功能（沿用既有決定：文件編輯仍透過 `/addyosmani-saspec` 對話或直接改 `.md` 檔）
- 不做使用者權限管理
- 不做 Jira 票狀態寫回文件（進度儀表板僅讀取顯示）

## 驗收條件

| 情境 | 操作 | 預期結果 |
|---|---|---|
| 瀏覽功能清單 | 開啟網站首頁 | 左側選單列出所有已產出規格的功能 |
| 瀏覽文件 | 點選某功能的「需求文件」 | 正確顯示該份文件內容，排版清楚 |
| 搜尋文件 | 輸入關鍵字搜尋 | 顯示包含該關鍵字的文件結果 |
| 查看進度儀表板 | 點選某功能的「進度儀表板」 | 顯示該功能對應的 Jira 票即時進度，含總數與狀態分類 |
| 深色模式 | 切換至深色模式 | 網站整體切換為深色主題，文字仍清楚可讀 |
| 資料不寫回 | 查看進度儀表板前後 | `tasks-*.md` 內容未被改動 |
