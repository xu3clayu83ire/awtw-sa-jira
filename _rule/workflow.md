# 工作流程規範（本專案補充）

> 基礎規範沿用工作區共用的 `_rule/workflow.md`，本檔案只記錄本專案獨有的差異。

## 版本標記策略

- 一般功能分支（`feature/*`、`fix/*`、`chore/*`）：沿用共用規範，merge 進 main 後照舊刪除，不永久保留
- **每個重要優化版本，在 merge 進 main 後對該 commit 打 annotated tag**，格式 `v<N>-<描述>`，供事後追溯每個版本對應的程式碼狀態
  - 命名範例：`v1-no-notion`（核心流程，不含 Notion 整合）
  - 之後每次做較大幅度的架構優化（例如加入 Notion 整合），完成並驗證通過、merge 進 main 後，打新的 `v2-<描述>` tag
  - 不使用永久保留分支來標記版本（分支語意是「還在開發中」，標記已完成的版本用 tag 才符合 Git 慣例）
