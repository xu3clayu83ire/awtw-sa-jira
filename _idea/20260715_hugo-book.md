# 網頁 UI 改用 Hugo + hugo-book 主題

目前 Frontend Phase 2 用 React + Vite 做的網頁（功能選單、文件檢視器、進度儀表板）排版很陽春，看起來很糟。想參考 `awtw-short-url-service` 的做法，改用 Hugo 的 `hugo-book` 主題呈現。

## 參考做法（`awtw-short-url-service-agent/hugo-docs`）

```toml
# hugo.toml
baseURL = "http://localhost:1313"
title = "awtw-short-url-service 技術文件"
theme = "hugo-book"
defaultContentLanguage = "zh-tw"

[params]
  BookMenuFromFiles = true
  BookToC = true
  BookSearch = true
```

那個專案是把 `_spec/` 底下的 markdown 規格文件直接放進 `hugo-docs/content/docs/`，用 hugo-book 渲染成一個左側選單、可搜尋、有目錄的文件站，體驗比現在陽春很多。

## 想要什麼

- `_spec/<功能>/` 底下的 `requirement.md`／`design.md`／`tasks-*.md` 能像文件站一樣瀏覽（左側選單依功能分類、有搜尋、有目錄）
- 排版好看，不用自己刻 CSS

## 已決定：進度儀表板怎麼跟 hugo-book 整合

**做法**：hugo-book 頁面裡嵌一段輕量 JavaScript（傾向用 Alpine.js，不用 React），直接 `fetch()` 呼叫現有的 backend proxy API（`GET /api/features/:feature/issues`、`GET /api/jira/issue/:key`，這兩個端點已經做好，不用重寫），畫面套用 hugo-book 自己的 CSS 樣式（不額外找 UI 元件庫），視覺才會跟文件站一致。

**選單結構**：左側選單每個功能（例如 `whisperx-transcription`）底下，除了 `requirement.md`／`design.md`／`tasks-*.md` 三個文件連結，多一條「進度儀表板」。

**儀表板畫面內容**（已用 mockup 確認過方向）：
- 上方摘要條：總票數／待辦事項／進行中／已完成，一眼看整體進度
- 下方票號列表（表格）：票號（等寬字體＋淺底色標籤）、任務標題、角色（frontend/backend/qa/devops）、執行方式（🤖 AI／👤 手動）、狀態（色塊圓角標籤：灰=待辦、琥珀=進行中、綠=完成）
- 淺色/深色主題都要支援
- 每 30 秒自動重新整理
